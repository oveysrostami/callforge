# CallForge

CallForge یک ابزار خط فرمان محلی و قابل‌ادامه برای ایندکس‌کردن فایل‌های MP3 و اجرای transcription با Codex و Whisper است. نام پروژه وابسته به نام پوشه یا PBX خاصی نیست و می‌توان هر دایرکتوری صوتی را به آن داد.

## قابلیت‌ها

- جست‌وجوی بازگشتی همهٔ فایل‌های `.mp3` با پشتیبانی از حروف بزرگ و کوچک
- استخراج hash، زمان و اندازهٔ فایل، مشخصات صوت و متادیتای نام تماس
- صف پایدار SQLite با retry، lease و تاریخچهٔ هر اجرا
- پردازش batch و اجرای هم‌زمان چند Codex worker
- اجرای مستقیم دو پاس Whisper با runtime نصب‌شده و cache پایدار مدل
- استفاده از Codex فقط برای مقایسهٔ خروجی‌ها، بازسازی نوبت‌های گفتگو و تولید Markdown
- ساخت Markdown هم‌نام کنار MP3
- ذخیرهٔ کامل همان Markdown به‌صورت نسخه‌دار در دیتابیس و رابطهٔ مستقیم با فایل صوتی
- واردکردن خودکار Markdownهای قبلی هنگام scan
- UI فارسی روی localhost برای جست‌وجو، مشاهدهٔ متادیتا، پخش صوت و خواندن transcript
- اجرای transcription یا transcription مجدد یک فایل مشخص مستقیماً از UI
- نمایش زندهٔ مرحله‌های پردازش، تلاش جاری و خطاها با stream داخلی SSE
- نگه‌داری تماس‌های نمایش‌داده‌شده با مدت `۰:۰۰` فقط به‌عنوان inventory با وضعیت `skipped`، خارج از آمار و transcription
- آماده برای stageهای آینده از طریق جدول‌های عمومی `jobs`، `processing_runs` و `artifacts`

نگاشت نوع تماس از روی پیشوند نام فایل انجام می‌شود:

- `external-`: تماس ورودی
- `internal-`: تماس داخلی به داخلی
- `out-`: تماس خروجی

## نصب سراسری از GitHub

Python 3.11 یا جدیدتر لازم است. نصب‌کننده آخرین نسخهٔ CallForge را مستقیماً از GitHub در یک محیط ایزوله و دائمی در فضای کاربر قرار می‌دهد و command سراسری `callforge` را می‌سازد. دیگر نیازی به clone کردن پروژه، ساخت `.venv`، اجرای `source` یا رفتن به دایرکتوری repository نیست و Python سیستم نیز تغییر نمی‌کند.

macOS و Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/oveysrostami/callforge/main/scripts/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/oveysrostami/callforge/main/scripts/install.ps1 | iex
```

نصب‌کننده `callforge setup --yes --force-skill` را اجرا می‌کند: Codex CLI و ورود حساب، FFmpeg، Whisper، skill، محیط جداگانهٔ pyannote/CTC و دانلود و بارگذاری مدل‌ها بررسی می‌شوند. نصب خودکار Codex به Node.js/npm نیاز دارد. در macOS/Linux اگر مسیر command برای اولین بار به PATH اضافه شود، یک terminal جدید باز کنید؛ activation یا `source` لازم نیست. اگر ورود تعاملی در نصب ممکن نباشد، command نصب می‌ماند و ادامه با `callforge setup` است.

### راه‌اندازی مدل‌ها و Hugging Face

```bash
callforge setup             # راهنمای تعاملی؛ نیازی به init یا دایرکتوری صوتی ندارد
callforge setup --yes       # نصب بدون سؤال اولیه؛ ورود توکن همچنان مخفی و تعاملی است
callforge setup --check     # فقط بررسی وضعیت، بدون نصب یا ورود
```

اگر دسترسی آماده نباشد، setup همین لینک‌ها را نمایش می‌دهد:

1. با حساب خود در [صفحهٔ community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) شرایط را شخصاً بپذیرید.
2. در [تنظیمات توکن Hugging Face](https://huggingface.co/settings/tokens)، توکن Read بسازید؛ توکن fine-grained باید مجوز خواندن مدل‌های gated را داشته باشد.
3. توکن را فقط در ورودی مخفی ترمینال وارد کنید؛ نه چت، آرگومان فرمان یا config. `--yes` به‌معنی پذیرش شرایط مدل نیست. ورود موفق بدون پذیرش شرایط کافی نیست؛ setup دسترسی مدل را جداگانه بررسی می‌کند.

توکن و مدل موجود استفادهٔ مجدد می‌شوند؛ Git credential ساخته نمی‌شود. مدل تطبیق کلمات فارسی در اولین نصب حدود ۱٫۲۶ گیگابایت دانلود دارد، به‌علاوهٔ Whisper و مدل تفکیک گوینده. setup تا بارگذاری موفق مدل‌ها کامل اعلام نمی‌شود. نصب تازه cache/runtime مشترک کاربر دارد و قبل از `init` قابل اجراست؛ نصب قدیمی از runtime/cache موجود استفاده می‌کند و مسیر آن در state کاربر ثبت می‌شود، بدون جابه‌جایی فایل‌ها. Whisper قدیمی cache خودش را حفظ می‌کند. بررسی `--check` نشان‌دهندهٔ آخرین تأیید setup است؛ برای بررسی مجدد واقعی بارگذاری مدل‌ها، setup را اجرا کنید.

setup تشخیص گوینده را برای workspace فعال روشن می‌کند و workspace جدید نیز پیش‌فرض روشن است. برای خاموش‌کردن آگاهانه، `diarization = false` در config بگذارید. پس از setup، UI قبلی را متوقف و دوباره اجرا کنید تا تنظیمات جدید بارگذاری شوند.

برای به‌روزرسانی نیز همان فرمان نصب را دوباره اجرا کنید؛ نصب‌کننده برنامه و نسخهٔ bundled مربوط به skill را با نسخهٔ GitHub هماهنگ می‌کند.

برای توسعه:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/callforge setup --yes
```

## شروع سریع

```bash
callforge init "/path/to/audio-root"
callforge status
callforge run --batch-size 5 --workers 2
callforge ui
```

`init` دایرکتوری صوتی را scan می‌کند و آن را به‌عنوان workspace فعال به خاطر می‌سپارد. بعد از آن `run`، `ui`، `status`، `retry` و `transcripts` در هر دایرکتوری سیستم قابل اجرا هستند و دیتابیس workspace فعال را پیدا می‌کنند. مسیر اجرای shell هیچ نقشی در انتخاب فایل‌ها ندارد.

فرمان `ui` بدون scan مجدد، دیتابیس موجود را باز می‌کند، مرورگر را اجرا می‌کند و رابط را به‌صورت پیش‌فرض روی `http://127.0.0.1:8765` بالا می‌آورد. فایل‌های frontend از قبل داخل پکیج build و بسته‌بندی شده‌اند؛ بنابراین نصب Node.js یا اجرای build جداگانه برای UI لازم نیست.

پس از انتخاب هر تماس، دکمهٔ «تبدیل به متن» همان فایل را در background پردازش می‌کند. اگر transcript فعلی وجود داشته باشد دکمه به «تبدیل مجدد» تغییر می‌کند؛ نسخهٔ قبلی تا موفق‌شدن پردازش جدید حفظ می‌شود و سپس transcript تازه به‌عنوان نسخهٔ جاری ثبت خواهد شد. تعداد پردازش‌های هم‌زمان UI از مقدار `workers` در `.callforge/config.toml` پیروی می‌کند.

هنگام پردازش، کارت «وضعیت زندهٔ پردازش» در جزئیات تماس نمایش داده می‌شود. این کارت بدون refresh صفحه، تلاش جاری، زمان پردازش کل و رویدادهایی مانند بررسی فایل، آماده‌سازی و تقویت صدا، اجرای Whisper، بازبینی و ثبت نتیجه را نشان می‌دهد. پس از اتمام یا شکست نیز timeline از بین نمی‌رود و با انتخاب دوبارهٔ فایل از log همان `processing_run` بازیابی می‌شود. خروجی خام commandها به مرورگر فرستاده نمی‌شود و stream فقط روی localhost و از طریق همان سرور UI در دسترس است.

برای انتخاب port یا جلوگیری از بازشدن خودکار مرورگر:

```bash
callforge ui --port 9090 --no-open
```

سرور عمداً فقط به localhost متصل می‌شود. اگر `--host 0.0.0.0` انتخاب شود، فایل‌های صوتی و transcriptها بدون احراز هویت در شبکه قابل دسترسی خواهند بود.

`batch-size` تعداد فایل‌هایی است که در هر بار از صف برداشته می‌شود. `workers` تعداد پردازش‌های هم‌زمان است. این دو عمداً جدا هستند، چون مدل‌های بزرگ Whisper حافظهٔ زیادی مصرف می‌کنند.

برای دیدن کار قابل انجام بدون اجرای Codex:

```bash
callforge run --batch-size 5 --workers 2 --dry-run
```

فرمان‌های دیگر:

```bash
callforge doctor
callforge scan "/path/to/audio-root"
callforge workspace
callforge transcripts --limit 20
callforge retry
callforge reset
```

`scan DIRECTORY` علاوه بر به‌روزرسانی فایل‌ها، همان دایرکتوری را workspace فعال می‌کند. بنابراین برای جابه‌جایی بین دو آرشیو کافی است دایرکتوری موردنظر را با `init` یا `scan` انتخاب کنید. `callforge workspace` مسیر دایرکتوری فعال و دیتابیس آن را نمایش می‌دهد.

## پاک‌کردن داده‌های دیتابیس

برای خالی‌کردن کامل دیتابیس workspace فعال:

```bash
callforge reset
```

برای حذف فقط رکوردهای مربوط به یک زیرشاخهٔ مشخص:

```bash
callforge reset "/path/to/audio-root/2026/04"
```

مسیر نسبی نیز نسبت به audio root فعال پذیرفته می‌شود:

```bash
callforge reset "2026/04"
```

این فرمان فایل‌های MP3 و Markdown را حذف نمی‌کند؛ فقط `audio_files` انتخاب‌شده و relationهای دیتابیسی آن‌ها شامل job، processing run، transcript و artifact پاک می‌شوند. قبل از حذف باید عبارت `RESET` را وارد کنید. برای اسکریپت‌های خودکار می‌توان confirmation را با `--yes` رد کرد:

```bash
callforge reset "2026/04" --yes
```

اگر یکی از فایل‌های هدف در حال پردازش باشد، reset انجام نمی‌شود. همچنین اجرای دوبارهٔ `scan` فایل‌هایی را که هنوز روی دیسک هستند مجدداً وارد دیتابیس می‌کند.

## فایل‌های هر workspace

با `init`، پوشهٔ زیر داخل دایرکتوری ورودی ساخته می‌شود:

```text
.callforge/
├── config.toml
├── callforge.sqlite3
├── logs/
├── models/
└── runs/
```

تنظیمات پیش‌فرض در `.callforge/config.toml` قابل تغییر‌اند:

```toml
[callforge]
batch_size = 5
workers = 2
max_attempts = 3
lease_seconds = 7200
whisper_timeout_seconds = 1800
codex_timeout_seconds = 600
codex_idle_timeout_seconds = 120
codex_reasoning_effort = "low"
codex_model = ""
codex_ignore_user_config = true
codex_ignore_rules = true
language = "fa"
skill_name = "pbx-call-transcriber"
whisper_model = "turbo"
whisper_retry_model = "turbo"
whisper_retry_segments = 3
whisper_retry_seconds = 120
glossary = ["ونسی", "بلوبانک", "بیت‌پین"] # اختیاری؛ فقط راهنمای املا
diarization = true
diarization_timeout_seconds = 180
alignment_timeout_seconds = 180
role_timeout_seconds = 180
```

## مدل داده

```text
audio_files 1 ─── * jobs 1 ─── * processing_runs
     │                            │
     └──── 1 ─── * transcripts ──┘
     │                    │
     └──── 1 ─── * artifacts ────┘
```

`transcripts.content` متن کامل Markdown را نگه می‌دارد و `markdown_path` مسیر نسخهٔ کنار فایل را ثبت می‌کند. هر ویرایش جدید یک نسخهٔ تازه می‌سازد و فقط یکی `is_current=1` است. در نتیجه فایل کناری خروجی قابل‌خواندن برای انسان است، ولی دیتابیس منبع ساخت‌یافتهٔ مرحله‌های بعدی باقی می‌ماند.

ارتقا به schema نسخهٔ ۵ خودکار و افزایشی است. قبل از تغییر دیتابیس موجود، snapshot سازگار SQLite در `.callforge/backups` ساخته می‌شود. reset دیتابیس، MP3/Markdown، لاگ‌ها و فایل‌های backup را پاک نمی‌کند.

## رفتار پردازش

در تطبیق دو پاس، هر کلمهٔ پاس تقویت‌شده تنها به یک بخش تعلق دارد؛ جملهٔ کامل در چند بخش هم‌پوشان تکرار نمی‌شود. اگر زمان کلمات معتبر نباشد، بخش‌های خام مربوط به همان جمله برای بازبینی یکپارچه می‌شوند و ابهام زمانی ثبت می‌شود. پاسخ کوتاهی که فقط در پاس دوم وجود دارد حذف نمی‌شود. این تغییر متن نسخه‌های قبلی یا تأییدشده را بازنویسی نمی‌کند.

برای مقایسهٔ آزمایشی مدل‌های MLX روی Apple Silicon، ابتدا با `benchmark-freeze` مرجع انسانی را ثابت کنید و سپس اجرا کنید:

```bash
callforge benchmark-asr --reference /absolute/path/reference.json \
  --model mlx-community/whisper-large-v3-turbo-q4 \
  --model mlx-community/whisper-large-v3-turbo \
  --output /absolute/path/new-experiment
```

`--reference` برای چند تماس تکرارپذیر است. مدل لازم در cache فعال دریافت می‌شود؛ زمان دانلود از سنجش پردازش جداست و revision در مسیر snapshot ثبت می‌شود. هر دو مدل با همان صدای خام/AGC و تنظیمات decode اجرا می‌شوند. متن انسانی فقط وارد امتیازدهی می‌شود، نه prompt مدل. گزارش WER/CER مربوط به **خروجی ASR قبل از بازبینی Codex** است؛ شمارش عدد، حروف عدد را معادل رقم نمی‌گیرد. این آزمایش فقط فایل‌های خروجی جدید می‌سازد؛ دیتابیس، متن تأییدشده، MP3/Markdown و مدل پیش‌فرض را تغییر نمی‌دهد. نتایج سه نمونهٔ توسعه تضمین کیفیت تماس‌های جدید نیستند.

هر worker با Python محیط نصب‌شدهٔ CallForge صوت را محلی decode می‌کند. تقویت صدا خطی، محدود به قله و فقط برای بخش‌های کم‌صداست؛ ورودی خام همیشه حفظ می‌شود. دو پاس مکمل Whisper (نه مستقل آماری) روی صدای خام و تقویت‌شده اجرا می‌شوند. برای فارسی یک prompt خنثی فقط زبان و نوع مکالمه را تثبیت می‌کند و واژه‌های glossary صرفاً به‌عنوان راهنمای املا به آن افزوده می‌شوند. هر دو backend زمان کلمات، معیارهای تشخیصی و VAD یکسان Silero را نگه می‌دارند. VAD برای پیدا کردن شکاف گفتار است، نه حذف قطعی صدای آهسته.

اگر VAD گفتار تشخیص دهد ولی هر دو پاس متن قابل‌استفاده نداشته باشند، CallForge شکاف‌های نزدیک را گروه‌بندی و در پنجرهٔ ۳۰ ثانیه‌ای دارای زمینه دوباره پردازش می‌کند؛ جمله‌های یک یا دو ثانیه‌ای جداگانه decode نمی‌شوند. متن بازیابی فقط با زمان کلمات به همان شکاف متصل می‌شود و خروجی دارای حلقه، معیار نامعتبر، فشردگی غیرعادی، احتمال سکوت، عدد کم‌اطمینان یا کپی prompt پذیرفته نمی‌شود. این بازیابی پیش از بازخوانی محدود سایر قسمت‌های مشکوک انجام می‌شود و مجموع هر دو همچنان به `whisper_retry_seconds` محدود است. صدای خام برای retry استفاده می‌شود مگر اینکه AGC شدت را دست‌کم ۲۰٪ بهتر کرده باشد.

مهلت پیش‌فرض هر مرحلهٔ Whisper سی دقیقه، هر تلاش بازبینی Codex ده دقیقه و بی‌فعالیتی Codex دو دقیقه است. Codex در sandbox فقط‌خواندنی از skill همراه همان نسخهٔ برنامه استفاده می‌کند و خروجی JSON مطابق schema می‌دهد؛ اجازهٔ نصب و پردازش دوبارهٔ صوت ندارد. ورودی فشرده، متن کامل تماس و گزینه‌های جایگزین را بدون انبوه جزئیات کلمات نگه می‌دارد. پایان موفق فرایند، حضور تک‌تک بخش‌ها و باقی‌نماندن حلقه‌های تکراری خراب بررسی می‌شود. «فایل ده ثانیه ثابت مانده» معیار پایان نیست؛ تنظیم قدیمی `codex_artifact_grace_seconds` فقط برای سازگاری خوانده می‌شود.

پس از timeout یا پاسخ ناقص، فقط بازبینی دوباره اجرا می‌شود؛ `codex_review_attempts` به‌صورت پیش‌فرض ۲ و قابل تنظیم از ۱ تا ۳ است. اگر همهٔ تلاش‌ها شکست بخورند، وضعیت پردازش «ناموفق» می‌شود؛ Markdown و نسخهٔ قبلی دیتابیس دست‌نخورده می‌مانند و هیچ پیش‌نویس خامی به‌عنوان متن نهایی منتشر نمی‌شود. شواهد و لاگ شکست در فایل و دیتابیس حفظ می‌شوند. این شکست باعث اجرای خودکار مجدد کل Whisper نمی‌شود. بازخوانی صوتی ابتدا به تکرارهای خراب و سپس سایر بخش‌های مشکوک اختصاص پیدا می‌کند.

اجرای Codex به‌صورت پیش‌فرض با `codex_ignore_user_config` و `codex_ignore_rules` از تنظیمات نامرتبط جدا می‌شود. مدل از `codex_model` یا مدل سطح بالای تنظیمات Codex گرفته می‌شود. `whisper_model` و `whisper_retry_model` مقدار `turbo`، `full` یا شناسهٔ مدل سازگار با backend می‌پذیرند؛ انتخاب `full` دانلود مدل بزرگ‌تر را در اولین استفاده انجام می‌دهد. بدون تغییر تنظیمات، Full دانلود نمی‌شود. JSONها و مشخصات اجرا در `.callforge/runs` و دیتابیس نگه داشته می‌شوند؛ WAVهای موقت پس از اجرا پاک می‌شوند. لاگ‌ها در `.callforge/logs` باقی می‌مانند. خروجی ماشین، حتی در صورت موفقیت، همیشه نیازمند بازبینی انسانی است.

## بازبینی انسانی و سنجش کیفیت

### آزمایش مرحله‌ای تشخیص گوینده

ابتدا آخرین اصلاحات تماس را در UI تأیید انسانی کنید. سپس یک snapshot ثابت از نسخهٔ انسانی و نسخهٔ ماشینی همان صوت بسازید:

```bash
callforge benchmark-freeze --audio-id 8497
```

فایل به‌صورت پیش‌فرض در `.callforge/benchmarks/audio-8497.json` فضای فعال ذخیره می‌شود. دستور مسیر مطلق را چاپ می‌کند؛ فایل موجود را بازنویسی نمی‌کند. برای یک مرجع جدید از `--output` با نام تازه استفاده کنید. این snapshot شامل متن خصوصی تماس است؛ آن را وارد Git نکنید. نسخهٔ در حال بازبینی یا صوت تغییرکرده پذیرفته نمی‌شود.

شرایط مدل `pyannote/speaker-diarization-community-1` را در Hugging Face شخصاً بپذیرید و یک توکن فقط‌خواندنی بسازید. توکن را داخل چت، فایل تنظیمات پروژه یا آرگومان فرمان قرار ندهید:

```bash
callforge setup
callforge benchmark-diarization --benchmark /absolute/path/to/audio-8497.json
```

setup ورود مخفی توکن، محیط جداگانه و دریافت مدل‌ها را انجام می‌دهد؛ فرمان‌های قدیمی `hf-login` و `setup-diarization` برای سازگاری باقی مانده‌اند. خود آزمایش فقط صوت خام را decode و گوینده‌ها را تفکیک می‌کند: هیچ Whisper/Codex اجرا نمی‌شود و Markdown و transcript دیتابیس تغییر نمی‌کنند.

گزارش و لاگ هر آزمایش در پوشهٔ جدید `.callforge/experiments` باقی می‌مانند؛ WAV موقت پاک می‌شود. امتیاز گوینده، تطبیق زمانی با بهترین نگاشت یک‌به‌یک شناسه‌ها روی بخش‌های مرجع است، نه DER کامل یا تشخیص نقش مشتری/پشتیبان. فاصله‌های بدون برچسب و هم‌پوشانی مرجع امتیازدهی نمی‌شوند. این معیار فعلاً برای نمونه‌هایی است که هر نقش دقیقاً یک نفر دارد. یک نمونهٔ توسعه برای اثبات کیفیت عمومی کافی نیست؛ holdout باید جدا بماند.

مرحلهٔ بعدی، اتصال گوینده‌ها به **متن ماشینی اولیه** و استنباط نقش از محتوای همان متن است:

```bash
callforge benchmark-roles --benchmark /absolute/path/to/audio-8497.json --diarization /absolute/path/to/speakers-experiment --timeout 180
```

`--diarization` دایرکتوری آزمایش موفق قبلی است؛ hash صوت و snapshot باید مطابقت داشته باشد. Whisper و تشخیص صوت دوباره اجرا نمی‌شوند. شناسه، متن و زمان هر بخش ثابت می‌ماند؛ کلمات خام Whisper جایگزین متن بازبینی‌شده نمی‌شوند. نقش‌ها در یک اجرای محدود Codex با همان مدل تنظیم‌شده، از متن ماشینی و شناسه‌های صوتی استنباط می‌شوند؛ متن انسانی، برچسب‌های قبلی و نگاشت بهترین امتیاز به مدل داده نمی‌شوند. برای هر نقش معلوم، شاهد دقیق از حداقل دو بخش همان گوینده لازم است؛ این کنترل ساختاری به‌تنهایی اثبات درستی استنباط نیست. بخش‌های مختلط، پوشش صوتی ناکافی و نقش نامطمئن نامشخص می‌مانند؛ تماس داخلی به مشتری/پشتیبان برچسب نمی‌خورد.

خروجی در دایرکتوری تازهٔ `.callforge/experiments/roles-*` شامل `input.json`، `aligned.json`، `roles.json`، `prediction.json`، پیش‌نمایش `preview.md`، لاگ‌های ماندگار و `report.json` با زمان پردازش و امتیاز است. `--output` مسیر تازهٔ دلخواه را می‌پذیرد. پاسخ ناقص، شاهد ساختگی، timeout یا استفادهٔ مدل از ابزار، آزمایش را ناموفق می‌کند. MP3، Markdown کنار آن و دیتابیس تغییر نمی‌کنند؛ قابلیت هنوز آزمایشی است و `run`/UI را خودکار فعال نمی‌کند. مدل نقش‌یاب متن را از طریق Codex دریافت می‌کند، نه فایل صوتی. امتیاز نقش از برچسب پیش‌بینی‌شدهٔ ثابت محاسبه می‌شود، نه جابه‌جایی بهینهٔ برچسب‌ها؛ هم‌چنان DER کامل یا دقت عمومی نیست.

برای آزمایش مرز کلمات در بخش‌های صوتی نامطمئن:

```bash
callforge setup-alignment
callforge benchmark-alignment --benchmark /absolute/path/to/audio.json --diarization /absolute/path/to/speakers-experiment
callforge benchmark-roles --benchmark /absolute/path/to/audio.json --diarization /absolute/path/to/speakers-experiment --alignment /absolute/path/to/alignment-experiment
```

هم‌ترازی فقط روی بخش‌های دارای گویندهٔ مبهم اجرا می‌شود؛ در هر تماس حداکثر ۴۰ بخش و هر بخش حداکثر ۳۰ ثانیه. مدل فارسی [Wav2Vec2 XLSR](https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-persian) با revision ثابت `234714078a1398a9db88194c5a40fefe6f376dc1` و Transformers 5.16.1 در runtime جداگانه استفاده می‌شود؛ این مدل در [WhisperX](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py) هم برای فارسی معرفی شده است، اما این پیاده‌سازی مستقل و آزمایشی است. نخستین اجرا وزن حدود ۱٫۲۶ گیگابایتی را دانلود می‌کند؛ `--timeout` در benchmark-alignment پیش‌فرض ۶۰۰ ثانیه است و برای دانلود کند قابل افزایش است. WAV خام ۱۶ کیلوهرتز فقط محلی استفاده و بعد پاک می‌شود. تنظیمات Whisper و `run`/UI عوض نمی‌شوند.

CTC فقط زمان کلماتِ متن ماشینی را تخمین می‌زند؛ عدد به حروف تبدیل نمی‌شود و `[نامفهوم]` یا کلمهٔ ناموجود در واژگان، زمان قابل‌اعتماد نمی‌گیرد. متن و زمان والد ثابت می‌ماند. نقش بخش تنها وقتی تکمیل می‌شود که دست‌کم ۶۰٪ کلمات شواهد صوتی کافی از یک گوینده داشته باشند و هیچ کلمهٔ قابل‌انتساب به گویندهٔ دیگر وجود نداشته باشد. بخش‌های مختلط یک نقش اکثریتی نمی‌گیرند. این آستانه‌ها قواعد توسعه‌اند، نه احتمال صحت. `word-review.md` در خروجی benchmark-roles جزئیات مرز و نقش هر کلمه را برای بازبینی نشان می‌دهد. لاگ و JSON هم‌ترازی، revision مدل و زمان بارگذاری/پردازش محفوظ می‌مانند. نمونه‌های انسانی فقط در امتیازدهی استفاده می‌شوند؛ تا آزمون چند نمونه و بازبینی مرزهای حساس، این مسیر برای انتشار عمومی فعال نمی‌شود.

روی Apple Silicon، گزینهٔ `benchmark-alignment --backend mlx ...` فقط از Whisper turbo موجود در cache استفاده می‌کند و دانلود را ممنوع می‌کند. این روش متن ثابت را با attention/DTW هم‌تراز می‌کند؛ متن تازه decode نمی‌شود و هیچ کلمه‌ای جایگزین نمی‌شود. بخش دارای عدد یا `[نامفهوم]` در این روش رد می‌شود. این شاهد مستقل از Whisper نیست و با CTC اشتباه گرفته نمی‌شود؛ روش و revision در گزارش ثبت می‌شوند. استفاده از CTC پیش‌فرض است؛ جایگزینی روش هرگز خودکار و پنهانی نیست.

در UI یک تماس دارای متن را باز کنید. «کارگاه بازبینی انسانی» امکان پخش هر بخش با سرعت دلخواه، مقایسهٔ متن خام/تقویت‌شده/بازخوانی تکمیلی، اصلاح زمان و گوینده و متن، افزودن یا حذف بخش و ثبت یادداشت را فراهم می‌کند. متن‌های قدیمی بدون زمان‌بندی هم ویرایشگر Markdown دارند؛ برای آن‌ها زمان جعلی ساخته نمی‌شود. وضعیت‌های `needs_review`، `in_review` و `approved` مستقل از وضعیت پردازش‌اند و فیلتر جدا دارند.

«ذخیرهٔ اصلاحات» یک نسخهٔ جدید با نام بازبین می‌سازد؛ «ثبت تأیید انسانی» مخصوص نسخه‌ای است که واقعاً شنیده و بررسی شده. نام بازبین در این ابزار localhost خوداظهاری است و احراز هویت محسوب نمی‌شود. تاریخچهٔ نسخه‌ها حفظ می‌شود. ویرایش مبتنی بر نسخهٔ قدیمی رد می‌شود. Markdown همگام می‌شود؛ اگر دیسک خطا بدهد یا فایل بیرون برنامه تغییر کرده باشد، اصلاح در دیتابیس باقی می‌ماند و فایل بیرونی بازنویسی نمی‌شود. پس از رفع مشکل و بازخوانی نسخه می‌توان همگام‌سازی را دوباره اجرا کرد.

```bash
callforge evaluation-sample --count 40 --seed 42 --output review-sample.json
# تماس‌های نمونه را در UI گوش کنید، اصلاح کنید و تأیید انسانی بزنید.
callforge evaluate --sample review-sample.json
```

نمونه‌گیری بر اساس جهت و طول تماس انجام می‌شود و بخشی از نمونه را به holdout اختصاص می‌دهد؛ این بخش نباید برای تنظیم prompt/مدل استفاده شود. گزارش WER/CER و خطای عدد، نسخهٔ ماشینی را با نسخهٔ تأییدشدهٔ همان صوت مقایسه می‌کند. بدون مرجع تأییدشده، نرخ خطا `null` است، نه صفر. برچسب‌های اختلاف و logprob «اعتماد قطعی» یا درصد دقت نیستند. بازبینی متنی به‌تنهایی تشخیص صوتی گوینده نیست و نقش نامطمئن باید نامشخص بماند.

فایل صوتی برای speech-to-text به سرویس خارجی ارسال نمی‌شود. بازبینی متن و استنباط نقش با Codex انجام می‌شود؛ بنابراین متن ماشینی به Codex داده می‌شود. مدل‌های تفکیک گوینده و تطبیق کلمات در setup دانلود می‌شوند و در پردازش تماس به‌صورت offline محلی بارگذاری می‌شوند.

از نسخهٔ 0.10.0 مسیر مشترک `run` و UI بعد از بازبینی متن، community-1 را روی صوت خام اجرا می‌کند، کلمات بخش‌های مبهم را با CTC فارسی تطبیق می‌دهد و سپس نقش را با همان مدل تنظیم‌شدهٔ Codex از شواهد هر صدای مشخص استنباط می‌کند. متن، اعداد و زمان بخش‌ها در این مراحل تغییر نمی‌کنند. ورودی مرجع انسانی در استنباط استفاده نمی‌شود. تعیین نقش به شواهد دقیق از حداقل دو بخش همان صدا نیاز دارد؛ موارد مبهم و تماس داخلی نامشخص می‌مانند. شناسهٔ صوتی هویت واقعی یا نقش فرد نیست. مراحل، زمان هر مرحله و دلایل نقش در شواهد ماندگار ذخیره می‌شوند و در UI قابل بررسی‌اند. شکست مرحله/timeout جلوی انتشار متن جدید را می‌گیرد؛ متن قبلی حفظ می‌شود و خطا در لاگ باقی می‌ماند. این مسیر محلی از سرویس ابری precision استفاده نمی‌کند و telemetry مدل غیرفعال است.

نسخه‌های مستقیم ASR در نصب‌کننده به ترکیب آزموده‌شدهٔ `mlx-whisper 0.4.3` و `faster-whisper 1.2.1` محدود شده‌اند؛ نسخه‌های runtime و تنظیمات هر اجرا در provenance ذخیره می‌شوند. پیش از استفاده از این نسخه `callforge setup --yes --force-skill` را اجرا کنید. مدل بزرگ‌تر، backend دیگر یا diarization تضمین بهبود روی تماس‌های شما نیست؛ با مجموعهٔ مرجع انسانی مقایسه کنید.
